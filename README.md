# Lexora

An installable, offline-first web app for learning English synonyms and antonyms with Bengali meanings.
Plain HTML, CSS and vanilla JavaScript. No framework and no build tools beyond Python.
It holds the 571 entries from the BCS preparation book (pages 231 to 248, A to Z).

## What it does
- **Spaced repetition.** Flashcards with three buttons. Forgot shows the word again in the same session. Hard returns in 3 days. Got it returns in 7 days, then 14, then 30, then longer. The next interval is shown under each button. An SM-2 ease factor and a Leitner box are kept inside each card.
- **Daily plan.** A quota of new words plus the due reviews. The quota is decided on the first visit each day and then frozen. It is paused when 60 or more reviews are waiting.
- **Study flow.** A numbered list of new words (cover answers, a tick per word, a star), then a test.
- **Modes.** Flashcards, reverse flashcards, multiple choice (distractors are never a valid synonym or antonym of the word), type the answer (any valid answer, small spelling slips tolerated), weak words, and read as a list.
- **Pick more words.** Read extra words from any letters without using up the daily plan.
- **Search.** Live search with letter index and filters. A word that appears as a synonym or antonym of other entries is shown under its own headword with those entries.
- **Sync.** Optional Google sign-in and Firestore sync (see `FIREBASE_SETUP.md`). Everything works offline and without signing in.

## Run locally
```
python3 -m http.server 8080
```
Open http://localhost:8080. Sign-in works on `localhost` once Google sign-in is enabled in Firebase.

## Rebuild the data
1. Edit `data/source/vocab_source.txt`. One entry per line: `page | word | pos | bengali | synonyms | antonyms | example | note | suggest`. Lists are separated by `, `.
2. Run `python3 tools/build.py`. It parses the file, verifies it, writes `data/data.json`, embeds it in `index.html` and refreshes `sw.js`. The build stops if any count disagrees.

The parser never skips, invents, translates or fixes an entry. It checks three ways: lines found by splitting the file, rows found by a separate regular expression, and a verbatim round trip (every entry is written back to a line and compared with the original, and `data.json` is re-read and compared again). `data/parse_report.txt` shows source rows, extracted entries, verified entries, rows per page, duplicate headwords and unclear entries. Nothing in those lists is changed.

### About the source
The PDF is a scan with no text layer, so rows cannot be counted from the PDF by machine. The source file is a transcription made by reading each page image. The parser verifies the transcription against itself and against the PDF's page count (18 pages, 18 pages covered), not against the pixels. Please spot-check against the book, especially the Bengali.
- Letters at the start of each synonym and antonym were capitalised, numbered senses ("1.", "2.") were joined into one list, and small bracketed hints and a few `(v)`/`(n)` tags were dropped. The pages below were not re-read for these.
- 36 entries carry an "Unclear in source" tag. They are kept exactly as printed, for example `Parise`, `Perimt`, `Clam`. The note says what looks wrong and `suggest` holds the probable spelling. Multiple choice never uses a flagged term, and typing accepts both the printed and the probable spelling.
- Part of speech is filled only where the Bengali cell marks it (one entry), so the part-of-speech filter in Search stays hidden until the data has more.
- Page 236's number was cut off in the scan and was taken from the page sequence.

## Deploy to GitHub Pages
1. Put the contents of this folder in the repository root (https://github.com/Arefin-Nahid/Lexora) and push to `main`.
2. In the repository, open **Settings > Pages**, choose **Deploy from a branch**, branch `main`, folder `/ (root)`, and save.
3. After a minute the app is at https://arefin-nahid.github.io/Lexora/. All paths are relative, so the sub-path works.
4. Add `arefin-nahid.github.io` as an authorized domain in Firebase (`FIREBASE_SETUP.md`, step 2).
5. After changing the code or data, run `python3 tools/build.py` and push again. The service worker gets a new version and phones update on the next open.

## Install on a phone
- **Android (Chrome):** open the site, then **Settings (gear) > Install app**, or Chrome menu > **Install app**.
- **iPhone or iPad (Safari):** tap Share, then **Add to Home Screen**.

## Tests
```
npm install
npm test
```
Python tests cover the parser (counts, round trip, duplicates, bad rows). Node tests cover the scheduler intervals, the frozen plan and projection, MCQ distractor safety across every entry, typing, session flows in jsdom, and a two-device sync test against a fake Firebase (offline queue, newest wins, counters adding up, no data bleeding between accounts).

## Not covered by the tests
The real Firebase calls and the Firestore rules were not run (they need your project and network access). Follow `FIREBASE_SETUP.md`, then sign in on two devices and check the progress appears on both. Language is English only; the setting is there for adding more later.
